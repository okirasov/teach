# Teach — мобильный клиент

React Native + Expo (SDK 57), Expo Router, TypeScript. iOS-first, Android поддерживается той же кодовой базой.

## Почему React Native + Expo, а не SwiftUI

- **Android обязателен.** SwiftUI дал бы вторую кодовую базу на Kotlin/Compose для всех девяти экранов и всей офлайн-логики. Один код на обе платформы — главный аргумент.
- **Дизайн уже описан в веб-терминах** (CSS-переменные, flex, px). Токены и вёрстка переносятся в RN почти один в один; SwiftUI потребовал бы переосмысления каждого размера.
- **Экосистема закрывает все требования брифа:** `expo-sqlite` (офлайн-first БД), `expo-secure-store` (токен отдельно от БД), `expo-apple-authentication` + `expo-auth-session` (Apple/Google), `expo-speech-recognition` (платформенный STT: SFSpeechRecognizer / Android SpeechRecognizer), `ts-fsrs` (FSRS без собственной реализации).
- **Скорость итераций:** hot reload, web-превью для проверки токенов, EAS для сборок. Бриф §5.2 сам склоняется к этому варианту при .NET-бэкенде.
- Цена: нативные модули (STT, Apple Sign-In) требуют dev-build, а не Expo Go. Это разовая настройка.

## Структура

```
mobile/
  app/                      # маршруты Expo Router (файл = экран)
    _layout.tsx             # шрифты, тема, Stack
    (auth)/sign-in.tsx      # авторизация
    (tabs)/                 # Сегодня · Повторы · Справочники · Предметы
    session/[id].tsx        # сессия урока / повторов
    recap.tsx               # разбор
    setup.tsx               # новый предмет (4 шага)
    subject/[id].tsx        # настройки предмета
    profile.tsx             # профиль
    ref/[id].tsx            # детальный справочник
  src/
    theme/                  # tokens.ts (DESIGN.md §2–3), typography.ts, ThemeProvider
    ui/                     # примитивы: Txt, Screen, Logo, Button, Card, Pill, Segment, Toggle…
    i18n/                   # словарь ru/en (из прототипа), типизированные ключи
    store/                  # zustand: settings (g), session, auth
    db/                     # expo-sqlite: схема, миграции, репозитории
    domain/                 # типы (Subject, Lesson, LearningRecord, ReviewItem, Reference) и FSRS
    features/               # логика экранов: session, reviews, refs, subjects
    voice/                  # STT-адаптер: push-to-talk / hands-free
  assets/
```

Правило: `app/` содержит только маршруты и композицию; всё, что можно протестировать без навигации, живёт в `src/`.

## Токены

`src/theme/tokens.ts` — палитра light/dark с именами CSS-переменных прототипа (`--mintInk` → `c.mintInk`), радиусы, отступы, размеры хит-таргетов. `src/theme/typography.ts` — Golos Text (400–700) и IBM Plex Mono (400–500) через `@expo-google-fonts/*`, именованные стили (`h1`, `question`, `kicker`, `chip`…). Доступ через `useTheme()`; текст — `<Txt t="h1" color="ink">`.

Тема выбирается в Профиле; до выбора следует системной.

## Иконки и релиз

`scripts/make-icons.py` рисует все иконки из знака бренда без внешних зависимостей (iOS без альфа-канала, adaptive-иконки Android, сплэш, favicon). Версия `expo.version` и `ios.buildNumber` в `app.json`; `ITSAppUsesNonExemptEncryption=false` снимает вопрос про шифрование в App Store Connect. Кнопка Google показывается только при заданных client id (в dev-сборке всегда). Демо-предметы («Английский», «Выступления») помечены чипом «демо».

## Хранилище

`src/db/` — expo-sqlite, файл на аккаунт (`teach-<accountId>.db`), миграции через `PRAGMA user_version`, таблицы `review_cards`, `review_log`, `kv`. Выход из аккаунта закрывает БД, файл остаётся. На web (только превью) — in-memory репозиторий с тем же интерфейсом.

Интервалы повторов — FSRS (`ts-fsrs`, без краткосрочных шагов): ошибка → 1 день, успех → 3 дня на новой карточке. Одна ссылка на шаг урока — одна карточка; повторное прохождение пересчитывает срок.

## Контент и прогрессия

`src/content/` — `ContentService`: локальная заглушка прототипа или `HttpContentService` при `EXPO_PUBLIC_CONTENT_URL` (сервер `server/`). Мастер создаёт предмет, сервер готовит диагностику в фоне; после каждого разбора записи уходят на сервер и готовится следующий урок, карточка на «Сегодня» показывает этапы, затем «Урок N · …». Пока идёт урок N, сессия просит сервер заготовить N+1 (`prefetchNextLesson`), и после «Готово» или × в разборе следующий урок обычно приходит сразу. Если приложение закрыли во время подготовки, вкладки при запуске продолжают ждать урок (`resumePrepare`), а не шлют разбор повторно. Опрос урока терпит сбои сети и ответы 5xx до трёх минут (`outageMs`, деплой сервера), 4xx — ошибка сразу; этапы «ищу источники → отбираю» показываются только для первого урока, следующий сразу «Собираю урок N». Длительность урока из настроек предмета (3/5/10 мин, по умолчанию 10) уходит на сервер и задаёт бюджет урока. Демо-предметы («Английский», «Выступления») статичны. Имя предмета — одно слово, максимум два коротких: его даёт сервер из формулировки темы, а без сети — `shortTitle` в заглушке (из «публичные выступления перед руководством» выходит «Выступления»). Название фокуса, которое печатается рядом с именем, сервер режет по словам до 30 символов. Язык предмета определяется при создании (`src/domain/languages.ts`) и задаёт локаль распознавания и подписи пилла «Язык распознавания».

## Запуск

```bash
npm install
npx expo start          # Metro для dev-сборки
npx expo start --web    # быстрый просмотр (SecureStore и SQLite заменены памятью)
npm run typecheck
npm test
```

Dev-переменные: `EXPO_PUBLIC_AUTH_LOCAL=1` — вход локальной сессией без провайдера (симулятор, автотесты); `EXPO_PUBLIC_GOOGLE_{IOS,ANDROID,WEB}_CLIENT_ID` — Google-вход; `EXPO_PUBLIC_CONTENT_URL=http://<host>:5180` — сервер-оркестратор (`server/`), без него мастер работает на локальной заглушке; `EXPO_PUBLIC_CONTENT_TOKEN` — bearer-токен сервера; `EXPO_PUBLIC_VOICE_SIM=1` — симуляция STT вместо платформенного; `EXPO_PUBLIC_VOICE_SMOKE=1` — дымовая проверка нативного STT при старте (лог `[voice]`).

## Повторы по предметам

Во вкладке «Повторы» над списками — вкладки предметов, как в справочниках: «Все» и предметы, у которых есть карточки. Вкладка предмета сужает списки и запускает повторы только по его карточкам (`useReviewPlan(subjectId)`, параметр `subject` у `/session/review`); «Все» оставляет повторы вперемешку — чередование предметов помогает запоминанию. Порядок вкладок и в повторах, и в справочниках тот же, что у предметов на «Сегодня» (`sortByOrder`, `src/features/subjects/order.ts`). «Справочники» тоже открываются на «Все»: видны справочники всех предметов, и в этом режиме на карточке подписан предмет. Вкладки появляются, когда предметов с данными больше одного.

«Сомневаюсь» в разборе — переключатель: повторное нажатие снимает отметку. На сервер отметка пока не уходит и ничего не проверяет.

Демо проходит цепочку статичных уроков; после последнего карточка показывает «Демо пройдено» и ведёт в мастер своего предмета. Миссии демо, добавленных после сохранения снимка, подставляются из сида при загрузке (`withSeedMissions`), поэтому в «Предметах» нет прочерка.

## Карточки повторов по урокам

Учебная точка — шаг конкретного урока: ссылка карточки хранит `subjectId`, номер урока и шаг, а также сам вопрос (`StepRef.snapshot`). Пересдача того же урока пересчитывает срок карточки, шаг нового урока создаёт новую — раньше ссылка была только на номер шага, и записи нового урока переписывали карточки старого, а повтор задавал вопрос из текущего урока. Повтор сначала берёт сохранённый вопрос; у карточки без снимка шаг ищется по номеру урока (`reviewStep`): у демо — в цепочке, начиная с первого урока, у своего предмета — в текущем уроке.

Старые карточки своих предметов чинятся при запуске и при возврате в приложение (`repairLegacyCards`): клиент один раз за запуск скачивает историю уроков предмета (`GET /subjects/{id}/lessons`), находит урок каждой карточки без снимка по заголовку записи в том же шаге и сохраняет номер урока и вопрос. Уроки перебираются с новых: раньше записи нового урока переписывали заголовок карточки, поэтому заголовок указывает на последний урок с этим шагом. Карточка без совпадения остаётся как была; при сбое сети попытка повторится при следующем возврате в приложение. Демо не чинятся: их старые карточки из первого урока цепочки и находятся правильно.

## Напоминания

Ежедневное локальное напоминание позаниматься (`expo-notifications`, `src/features/reminders/`). Час берётся из слота профиля: утро 9:00, вечер 19:00; «тихие выходные» превращают ежедневный триггер в пять недельных, без субботы и воскресенья (`reminderSchedule` — чистая функция, покрыта тестами). Разрешение спрашивается не при первом запуске, а когда напоминания включены. Расписание перестраивается при смене настроек и снимается при выходе. Сервер не участвует, работает офлайн.

Удалённых push-уведомлений о готовности урока пока нет: для них нужен либо EAS-проект (Expo держит ключи APNs), либо ключ APNs `.p8` и отправка из сервера — то и другое требует учётных данных. Практический разрыв закрыт иначе: возврат приложения из фона перезапускает опрос готовности (`AppState` в `app/(tabs)/_layout.tsx`), поэтому урок, доготовившийся в фоне, появляется сразу.

## Оценка свободного ответа

Свободный ответ оценивает сервер по смыслу (`/grade/free`, `claude-haiku-4-5`): «Vorrei un biglietto, gentilmente» засчитывается как вежливая просьба, хотя ключевого «per favore» в ней нет. Вызов идёт при нажатии «Ответить» с потолком в 4 секунды (`src/features/session/gradeFree.ts`); если сервер молчит, недоступен или вернул не столько флагов, сколько критериев, ответ проверяется по ключевым словам — так же, как офлайн. Оценка хранится в ответе шага (`StepAnswer.hits`) и не переносится на следующий шаг. Поле ответа вмещает ответ целиком: 132 pt для короткого и 200 pt для развёрнутого (`InputView`), текст переносится, а не прокручивается в узкой строке.

## Доступ к серверу

Токен из сборки (`EXPO_PUBLIC_CONTENT_TOKEN`) — запасной. После входа по Apple клиент меняет identityToken на токен аккаунта (`POST /auth/apple`) и дальше ходит с ним: предметы одного человека не видны другому. Токен живёт в SecureStore (`src/content/apiToken.ts`), подтягивается при старте до первых запросов, выход возвращает к токену сборки. Сбой обмена не блокирует вход — приложение продолжает работать с общим токеном.

## Несколько предметов

Пользовательских предметов может быть сколько угодно. Стор (`src/store/progress.ts`) хранит их по id: `subjects`, `lessons` (текущий урок каждого), `prep` (этап и ошибка подготовки каждого) — раньше это были одиночные `custom`/`customLesson`/`prepStage`/`prepError`. Порядок на экранах — по `createdAt` (`userSubjectIds`). Id выдаёт монотонный счётчик `seq` (`s1`, `s2`, …) и никогда не переиспользует: иначе новый предмет унаследовал бы карточки повторов и справочники удалённого, чьё удаление ещё не дошло до SQLite. Исторический id `custom` появляется только у предмета, перенесённого со старой версии: его карточки и справочники в SQLite уже привязаны к нему, поэтому данные тестировщиков переживают обновление. Снимок kv старой версии приводит к новой форме `migrateProgressSnapshot`, подключённый как `migrate` в `persistSlice`. Этап подготовки сохраняется (`prepStages`), а ошибка — нет (`prepErrors`): после перезапуска прерванная подготовка должна возобновиться сама, а не остаться навсегда «неудачной».

Подготовка идёт по предмету: все функции в `src/features/subjects/prepare.ts` принимают `subjectId`, `resumePrepare` после перезапуска поднимает все прерванные подготовки сразу, а `inFlight` не даёт запустить вторую генерацию того же предмета (она перезаписала бы урок первой и потратила вызов модели). Ошибка подготовки одного предмета не помечает остальные.

## Навигация по шагам урока

Движок сессии (`src/features/session/engine.ts`) различает активный шаг (`step`, самый дальний достигнутый) и показанный (`view`). Ответы пройденных шагов замораживаются в `answers[i]`, у активного они живые. Свайп вправо (`usePanGesture` из react-native-gesture-handler v3, `activeOffsetX` ±24, `failOffsetY` ±16, чтобы не мешать вертикальной прокрутке) показывает предыдущий шаг с ответом и разбором, свайп влево — следующий до активного; с активного неотвеченного шага вперёд нельзя, с отвеченного свайп равен «Дальше», но в разбор ведёт только кнопка. На пройденном шаге ввод, микрофон и выбор отключены, кнопка «К текущему шагу» возвращает к активному, озвучка работает.

## Первый запуск и пустое состояние

После первого входа показывается интро (`app/intro.tsx`, четыре экрана про метод, свайп или «Дальше»; флаг `settings.introSeen` в kv аккаунта), затем мастер первого предмета, если предметов нет. Демо-предметов два, `src/domain/demo/{en,speak}.ts`: «Английский» (фокус «Рассказ о себе», миссия «проходить собеседования на английском») и «Публичные выступления» (фокус «Структура речи», миссия «уверенно выступить перед командой на 10 минут»). Оба сгенерированы живым сервером 10 сентября 2026: источники через web search, план на пять этапов (`claude-sonnet-5`), стартовая диагностика, разбор и урок 2, глоссарий из диагностики; в код зашита цепочка уроков 2–6 с планом и глоссарием после каждого урока (`demoLessons`, `src/domain/demo/*.ts`, генерирует `emit.py` из ответов сервера). Разборы при генерации подавались с ошибкой в уроках 2 и 4, поэтому следующий урок разбирает её, а этап плана сменяется после двух уверенных уроков: уроки 2–3 на этапе 1, 4–5 на этапе 2, урок 6 на этапе 3. Позиция демо — `progress.demoStep`; после «Готово» открывается следующий урок и пополняется глоссарий (`goToNextDemoLesson`), после урока 6 карточка ведёт в мастер своего предмета. Карточки повторов (`demoQueue`: по одной «сегодня» и «позже» на предмет) и глоссарии засеваются один раз на базу аккаунта (`seedDemo`, флаг `demo.seeded.v3`); миграция v3 перед этим вычищает данные прототипа. Уроки прототипа (en/qa/hist) лежат в `src/domain/__fixtures__` только для тестов. Вкладки без предметов показывают подсказку и кнопку «Новый предмет».

Крестик в уроке не теряет прогресс: снимок сессии (`snapshot` в движке) сохраняется в `progress.sessions[subjectId]` и восстанавливается при следующем открытии того же урока (`restoreSession` сверяет отпечаток: заголовок, число шагов, набор карточек в повторах). Снимок удаляется после разбора и при получении нового урока.

## Голос

`src/voice/` — адаптер `SpeechRecognizer`: платформенный STT через `expo-speech-recognition` (SFSpeechRecognizer / Android SpeechRecognizer, только dev-сборка) и симуляция прототипа (web, `EXPO_PUBLIC_VOICE_SIM=1`). Режим из Профиля: «Удерживать» — одна реплика на pressIn/pressOut, «Без рук» — continuous до повторного тапа. Язык распознавания — из настроек предмета; в сессии повторов, где шаги собраны из карточек разных предметов, язык и настройки голоса берутся у предмета карточки текущего шага (`stepSubjectId`). Если STT недоступен или разрешение не дано, кнопка микрофона не показывается; текстовый ввод доступен всегда. В iOS-симуляторе SFSpeechRecognizer не инициализируется («Failed to initialize recognizer») — реальное распознавание проверяется на устройстве.

Озвучка (`src/voice/tts.ts`, `expo-speech`): системный синтез на устройстве, без сети и без токенов. Кнопка «динамик» (`SpeakButton`) у карточки «ПРИМЕР», у вариантов выбора, реплик для упорядочивания и правильного ответа; язык голоса — язык предмета, выключается в настройках предмета («Озвучка примеров»). Для неязыковых предметов и при отсутствии голоса на устройстве кнопок нет (`SpeakerProvider` проверяет `getAvailableVoicesAsync`). Смешанный текст режется по письменности (`src/voice/segments.ts`): кириллица читается голосом языка интерфейса, остальное — голосом предмета, куски идут по очереди. Смена шага и выход из сессии останавливают речь.

### iOS-симулятор на этой машине

`npx expo run:ios` выбирает спаренный физический iPhone и падает на подписи; CocoaPods под Ruby 4 требует UTF-8 локали. Рабочий путь:

```bash
LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 npx expo prebuild --platform ios
cd ios && xcodebuild -workspace Teach.xcworkspace -scheme Teach -configuration Debug -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -derivedDataPath build CODE_SIGNING_ALLOWED=NO build
xcrun simctl install booted build/Build/Products/Debug-iphonesimulator/Teach.app && xcrun simctl launch booted app.teach.mobile
```

### Сборка на iPhone

Команда `PW7867VU3L` прописана в `app.json` (`ios.appleTeamId`). На телефоне должен быть включён Developer Mode (Настройки → Конфиденциальность и безопасность), Mac и iPhone в одной Wi‑Fi сети (Debug-сборка грузит JS с Metro по адресу из `ip.txt`).

```bash
cd ios && xcodebuild -workspace Teach.xcworkspace -scheme Teach -configuration Debug -sdk iphoneos -destination 'id=<UDID>' -derivedDataPath build-device -allowProvisioningUpdates -allowProvisioningDeviceRegistration DEVELOPMENT_TEAM=PW7867VU3L build
xcrun devicectl device install app --device <UDID> build-device/Build/Products/Debug-iphoneos/Teach.app
xcrun devicectl device process launch --terminate-existing --device <UDID> app.teach.mobile
```

Release с встроенным бандлом (без Metro, без dev-входа, реальный Apple Sign-In): те же команды с `-configuration Release`, артефакт в `build-device/Build/Products/Release-iphoneos/Teach.app`. Профиль команды содержит `com.apple.developer.applesignin`.

UDID телефона: `xcrun devicectl list devices`. Проверено 2026-09-09: нативный STT на iPhone 16 Pro Max отдаёт промежуточные результаты по словам и финальную фразу.

### TestFlight

Архив и загрузка идут локально через сессию Apple ID в Xcode, ключ App Store Connect API не нужен:

```bash
cd ios && cp ../ExportOptions.plist . && export EXPO_PUBLIC_CONTENT_URL=https://teach-tutor-api.fly.dev EXPO_PUBLIC_CONTENT_TOKEN=$(cat ../../server/.secrets/api-token)
xcodebuild -workspace Teach.xcworkspace -scheme Teach -configuration Release -sdk iphoneos -destination 'generic/platform=iOS' -archivePath build-device/Teach.xcarchive -allowProvisioningUpdates DEVELOPMENT_TEAM=PW7867VU3L archive
xcodebuild -exportArchive -archivePath build-device/Teach.xcarchive -exportOptionsPlist ExportOptions.plist -exportPath build-device/export -allowProvisioningUpdates
```

Перед каждой новой загрузкой увеличить `ios.buildNumber` в `app.json` и выполнить prebuild. Предупреждения «Upload Symbols Failed» для React/hermes безвредны. Первая сборка 0.1.0 (1) загружена 2026-09-09.

Metro без watchman не видит правок — после изменения кода перезапускать `expo start --clear`. Разрешение на распознавание речи `simctl privacy` не выдаёт; в симуляторе его можно проставить в `~/Library/Developer/CoreSimulator/Devices/<UDID>/data/Library/TCC/TCC.db` (`kTCCServiceSpeechRecognition`, `auth_value=2`).
