# Как подключается AI для генерации контента

Дата: 2026-09-08, обновлено 2026-09-09. Статус: сервер `server/Teach.Api` и `HttpContentService` в клиенте реализованы; сквозной контур проверен на заглушке модели, прогон с реальным ключом Claude впереди.

## Принцип

Клиент не зовёт модель. Он говорит с оркестратором на сервере (.NET, бриф §5.1), а оркестратор
говорит с моделью. Причины: ключи не попадают в приложение, промпты правятся без релиза в сторах,
уроки кэшируются между пользователями с похожими миссиями, стоимость под контролем.

В клиенте уже есть единственная дверь к генерации: интерфейс `ContentService`
(`mobile/src/content/types.ts`). Сейчас его реализует локальная заглушка с данными прототипа.
Подключение сервера — это вторая реализация того же интерфейса поверх HTTP, экраны не меняются.

## Что генерируется и когда

| Момент | Метод ContentService | Что делает модель | Когда показываем |
|---|---|---|---|
| Мастер, шаг «Сужение» | `suggestFocus(topic)` | 3 фокуса с описаниями по теме | сразу, ждём ответ (~2 с) |
| Мастер, шаг «Источники» | `findSources(topic, focus)` | 4 источника с уровнем доверия | сразу; web search, ~2 мин на `claude-opus-5` |
| Мастер, шаг «План» | `buildPlan(draft)` | 3 этапа плана под миссию | сразу |
| После «Готово» | `prepareFirstLesson(draft)` | стартовая диагностика | в фоне: карточка «Готовится…» → «Урок готов» |
| После каждого разбора | `prepareNextLesson(subjectId)` (добавится) | следующий урок по записям об усвоенном | в фоне, к следующему заходу |
| Свободный ответ в сессии | `gradeFreeAnswer(step, text)` (добавится) | оценка по критериям вместо поиска ключевых слов | онлайн; офлайн — текущая проверка по ключам |

Повторы, справочники и глоссарий модель не трогает: сроками владеет FSRS, справочники
конденсируются из уже сгенерированных уроков на сервере.

## Контракт урока

Модель не изобретает разметку. Она заполняет фиксированную схему `Lesson`
(`mobile/src/domain/types.ts`): шаги `explain | choice | input | order | free` с полями
`recTitle`/`recNote` (будущая LearningRecord) и ссылкой на источник. Ответ модели запрашивается
как структурированный вывод (`output_config.format` с JSON-схемой), поэтому парсинг
детерминированный, а невалидный JSON невозможен на уровне API.

**Схема на проводе компактнее доменной.** У структурированного вывода жёсткий лимит сложности схемы:
полная схема шага с 21 полем и вложенными массивами (`tokens: string[][]`, `criteria: {t, keys[]}[]`)
отвергается API с ошибкой `Schema is too complex`. Поэтому модель заполняет плоский шаг из 13 полей,
а сервер разворачивает его в доменный (`ClaudeLessonModel.RawStep`):

| Поле схемы | explain | choice | input | order | free |
|---|---|---|---|---|---|
| `title` | заголовок | — | — | — | — |
| `text[]` | абзацы | варианты | группы токенов, синонимы через `\|`: `«if i were \| if i was»` | элементы | критерии `«текст \| ключ1, ключ2»` |
| `example`, `source` | пример, источник | — | — | — | — |
| `prompt`, `explain`, `recTitle`, `recNote` | — | ✓ | ✓ | ✓ | ✓ |
| `correct` (int) | — | индекс верного, `-1` — калибровка | — | — | — |
| `order` (int[]) | — | — | — | индексы в правильном порядке | — |
| `answer`, `placeholder` | — | — | ✓ | — | `placeholder` |

`why` («миссия · …») модель не пишет, его ставит сервер из миссии предмета. Пустой `text` у `input`
означает «принимается любой текст» (свободный рассказ в диагностике).

Поверх схемы сервер валидирует смысл (`LessonValidator`, бриф §5.4): 2–5 вариантов без дублей и
`correct` в диапазоне, `order` — перестановка индексов, у `free` 2–5 критериев с ключами, у каждой
практики заполнены `recTitle`/`recNote`, у объяснения есть источник, длина в бюджете длительности
урока (3/5/10 мин → 1400/2200/4000 символов), один урок — одна цель. Не прошло — повтор генерации,
до `MaxAttempts`, потом статус `failed`; пользователю невалидный урок не показывается.

## Вызов модели на сервере

Модель по умолчанию — `claude-opus-5` (Anthropic SDK для .NET, пакет `Anthropic`). Форма запроса:

```
system  = [ методика teach (принципы §2 брифа), формат урока, правила валидации ]   ← cache_control
user    = [ миссия предмета, план, выбранные источники ]                            ← cache_control
        + [ последние записи об усвоенном, настройки предмета: длительность, сложность ]
        + [ «собери урок N по этапу плана 02» ]
thinking = { type: "adaptive" }, output_config = { effort: "high", format: { json_schema: Lesson } }
```

Вспомогательные вызовы мастера (фокусы, источники, план) идут с `effort: medium`, web search ограничен
тремя запросами. Замеры первого прогона (2026-09-09): фокусы 5 с, план 6 с, источники 2 мин 12 с,
оценка свободного ответа на `claude-haiku-4-5` 1.4 с и по смыслу («укрепления и проливы» засчитаны
как «стены и море» без совпадения ключевых слов).

- **Кэш промпта.** Методика и формат урока неизменны для всех, миссия и источники — для предмета.
  Оба слоя помечены `cache_control`, меняется только хвост с записями. Это основная экономия:
  кэшированные токены стоят ~10 % от полной цены.
- **Источники.** На шаге `findSources` серверу нужен реальный поиск, а не память модели:
  серверный инструмент `web_search` с `allowed_domains` для академических и официальных
  источников, `max_uses: 5`. Уровень доверия проставляет модель по правилам из системного промпта.
- **Диагностика.** Первый урок не требует поиска: мастер передаёт выбранные источники в `POST /subjects`
  (`sources`), воркер не ищет их заново и сразу генерирует урок.
- **Проверка свободного ответа.** Дешёвая задача классификации: критерии + текст → какие покрыты.
  Здесь уместен `claude-haiku-4-5` с `max_tokens` ~256, ответ структурированный.
- **Фон.** Сервер ставит задачу в очередь после разбора; статус урока клиент читает при открытии
  «Сегодня» (`GET /subjects/{id}/next-lesson`) и по push. Готовый урок скачивается в SQLite и
  дальше доступен офлайн.
- **Промпты версионируются** отдельно от кода (таблица `prompts` с версией), в логе урока
  хранится версия промпта и id ответа модели.

## HTTP-контракт для клиента

```
POST /subjects/focus            { topic }                       → FocusOption[]
POST /subjects/sources          { topic, focus }                → SourceCandidate[]
POST /subjects/plan             { topic, focus, mission }       → PlanStage[]
POST /subjects                  SubjectDraft                    → { subjectId, status: "preparing" }
GET  /subjects/{id}/lesson      → { status: "preparing", stage: 0..2 } | { status: "ready", lesson }
POST /sessions/{id}/recap       { records }                     → 202 (ставит генерацию следующего)
POST /grade/free                { criteria, text, lang }        → { hits: boolean[] }
```

`HttpContentService` реализует `ContentService`, `prepareFirstLesson` = `POST /subjects` +
поллинг `GET …/lesson` до `ready` с `onStage` на каждом переходе. Без сети мастер не запускается
(поиск источников невозможен), остальное приложение работает из SQLite.

## Стоимость (оценка)

Урок на 5 минут — примерно 2–3 тыс. токенов вывода и 6–8 тыс. на входе, из них 5–6 тыс.
кэшированных. При `claude-opus-5` ($5 вход, $25 вывод за 1M) это около $0.08–0.10 за урок,
проверка свободного ответа на Haiku — доли цента. Кэш уроков между похожими миссиями (ключ:
цель урока + уровень) снижает это дальше.

## Порядок работ

1. ✅ `HttpContentService` в клиенте, флаг `EXPO_PUBLIC_CONTENT_URL`: без него — локальная заглушка. Сбой сервера не блокирует: карточка предмета предлагает «Повторить».
2. ✅ Сервер: `POST /subjects/*`, схема урока, валидация, фоновая диагностика (`server/README.md`). Осталось прогнать с `ANTHROPIC_API_KEY`.
3. Фоновая генерация следующего урока после разбора (записи уже принимаются `POST /sessions/{id}/recap`), статус и push.
4. Оценка свободных ответов моделью в клиенте (`/grade/free` готов на сервере) с офлайн-фолбэком по ключам.
5. Конденсация справочников из уроков.
