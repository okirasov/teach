1

Назначение и границы

Teach — мобильный репетитор по любой теме, не только по языкам. Пользователь формулирует, что и зачем хочет освоить; система строит короткие уроки на источниках, проверяет практикой без подсказок, превращает ошибки в записи и возвращает их как карточки повторов. Аудитория первой версии — автор и команда, монетизация вне рассмотрения.

В границах

  • Вход через Apple, локальный профиль настроек.
  • Создание предмета: тема, сужение, миссия, источники, план.
  • Уроки из фиксированного набора блоков, сессия на телефоне, разбор.
  • Повторы по FSRS, справочники, голосовой ввод ответов.
  • Серверная генерация уроков, справочников и оценка свободных ответов.

Вне границ первой версии

  • Синтез речи и голосовой диалог с моделью.
  • Сообщества и внешние площадки практики (бриф §2.10).
  • Командная аналитика, экспорт данных, оплата.
  • Веб-версия: web используется только для превью разработчика.

Метод как источник требований

Принципы из брифа §2, которые напрямую диктуют поведение интерфейса. Каждый принцип ниже имеет требования, ссылающиеся на него.

ПринципЧто это значит для продукта
M-1Миссия — якорь.Каждый урок отвечает, зачем он, ссылкой на миссию; миссия версионируется, история не удаляется.
M-2Знания из источников.Уроки строятся на найденных материалах с уровнем доверия, у объяснения есть источник.
M-3Знание лёгкое, навык трудный.Объяснение мягкое, практика без подсказок, разбор только после попытки.
M-4Ошибки — память системы.Каждая практика создаёт запись об усвоенном; из записей считаются повторы, следующий урок и пометки в справочниках.
M-5Урок — одна победа.Одна цель, один цикл практики, жёсткий бюджет длины.
M-6Зона ближайшего развития.Следующий шаг и этап плана выбираются по записям, не по самооценке и не по номеру урока.
M-7Справочники живут дольше уроков.Сжатая суть конденсируется из уроков и доступна офлайн.

Роли и сущности

Одна роль — ученик. Тестировщик и автор пользуются тем же интерфейсом. Сущности повторяют модель данных брифа §5.3.

СущностьСодержаниеГде живёт
SubjectТема, короткое имя, фокус, язык предмета, источники, план, текущий этапклиент (SQLite) + сервер
MissionТекущая формулировка и история версийклиент
LessonШаги explain / choice / input / order / free с записями recTitle и recNoteсервер, копия в клиенте
LearningRecordЧто оказалось неочевидным, результат, номер урока, этапсервер + карточки в клиенте
ReviewItemКарточка повтора с состоянием FSRS и журналом ответовклиент
ReferenceСправочник: группа, название, строки «термин | описание», пометка ошибкиклиент, глоссарий с сервера
SettingsЯзык, тема, напоминания, лимит повторов, режим записи; настройки предметаклиент

Новый предмет

Мастер из пяти шагов, создаётся с вкладки «Предметы». Каждый сетевой шаг показывает состояние загрузки и ошибку с повтором, кнопка «Дальше» ждёт данных.

04Источникичетыре с уровнем доверия, исключение тапом
05Плантри этапа, эхо миссии
IDТребованиеСтатус
FR-10Короткое имя предметаИз формулировки темы сервер даёт имя до 24 символов («Итальянский»); оно идёт в карточки, пиллы и название уроков, полная формулировка остаётся описанием.Реализовано
FR-11Язык предметаОпределяется при создании по таблице из 20 языков: код для распознавания речи и локализованные имена ru/en.Реализовано
FR-12Источники через поиск, не из памяти моделиWeb search на сервере, уровень доверия высокое/среднее/низкое; выбор пользователя передаётся в генерацию. Поиск идёт фоновой задачей с опросом статуса (M-2).Реализовано
FR-13Первый урок готовится в фонеПосле «Готово» экран закрывается сразу; карточка на «Сегодня» проходит этапы «Ищу источники → Отбираю по доверию → Собираю первый урок», затем «Урок готов». Без спиннера. Следующие уроки этапов поиска не показывают: сразу «Собираю урок N».Реализовано
FR-14Первый урок — стартовая диагностикаКалибровка без правильного ответа (бейдж «ПРИНЯТО»), свободный рассказ, одна настоящая проверка по источнику без подготовки: над ней кикер «СТАРТ» с подписью «этому ещё не учили», в разборе она показана как «ТОЧКА ОТСЧЁТА», не как ошибка. Всё уходит в записи.Реализовано
FR-15Сбой генерации не блокируетПредмет остаётся, карточка показывает «Не удалось собрать урок» и предлагает «Повторить»; удалённый во время подготовки предмет не воскресает. Опрос терпит сбои сети и 5xx до трёх минут (деплой сервера), 4xx — ошибка сразу.Реализовано
FR-16Несколько предметовПредметов может быть сколько угодно: у каждого свой урок, состояние подготовки, прерванная сессия, повторы, справочники и настройки. Id выдаёт монотонный счётчик и не переиспользует после удаления; предмет со старой версии сохраняет свой id, поэтому его данные переживают обновление.Реализовано

FR-27Выход крестикомИз сессии — без сохранения, как в прототипе. Из разбора крестик равен «Готово»: ошибки уже случились и должны стать памятью системы, записи сохраняются и следующий урок запускается (M-4).Реализовано

Прогрессия и план

IDТребованиеСтатус
FR-30Следующий урок по записямПосле каждого разбора сервер генерирует урок N: закрыть самую свежую ошибку, не повторять верное; промпт получает этап плана явно, длительность из настроек предмета задаёт бюджет (M-6).Реализовано
FR-31Этап плана по результатамЭтап закрывается, когда два последних урока этапа сделаны на ≥ 75 % и ≥ 60 % с первой попытки, диагностика не в счёт; страховка — после шести уроков этап закрывается в любом случае.Реализовано
FR-32Индикатор этапа на карточкеТри сегмента и строка «Этап N/3 · название · урок K»; этап приходит с сервера.Реализовано
FR-33Живой планПерестройка этапов плана по записям, а не только переход между ними; план как редактируемый объект.План
FR-34Два демо-предмета«Английский» (собеседования, фокус «Рассказ о себе») и «Публичные выступления» (миссия «уверенно выступить перед командой на 10 минут»). Сгенерированы живым сервером: источники, план на пять этапов, диагностика и урок 2 с глоссарием; зашиты статично с индикатором «Этап 1/5 · урок 2» и чипом «демо», следующих уроков у них нет. Карточки повторов и глоссарии засеваются один раз на аккаунт.Реализовано
FR-35Предзагрузка одного урока вперёдКогда открыт урок N, сервер заготавливает N+1 на текущем этапе по записям на этот момент. После разбора заготовка отдаётся сразу, если этап не сменился и верных ответов не меньше половины; иначе выбрасывается, и урок собирается заново по свежим записям. Дальше одного урока не генерируем: следующий шаг должен видеть последние ошибки (M-6).Реализовано
FR-37Подготовка предметов независимаНесколько предметов могут готовиться одновременно: этап и ошибка хранятся по предмету, сбой одного не помечает остальные. Вторая генерация того же предмета не запускается. Сбой первого урока после создания предмета на сервере повторяется дожиданием, а не вторым предметом.Реализовано
FR-36Возобновление после перезапускаЕсли приложение закрыли, пока урок готовился, при запуске клиент продолжает ждать урок с сервера, не отправляя разбор повторно; карточка не зависает на «Готовится…».Реализовано

Сервер и генерация

Клиент не держит ключей модели и не планирует обучение. Оркестратор на сервере собирает контекст, зовёт модель, валидирует ответ и хранит уроки, записи и справочники.

IDТребованиеСтатус
SR-01Единый интерфейс контентаКлиент ходит только в ContentService; реализация HTTP включается адресом сервера, без него — локальная заглушка.Реализовано
SR-02Структурированный вывод по схемеМодель заполняет плоскую схему шага; сервер разворачивает её в доменный урок; заголовок карточки, строку уровня «этап N · фокус» и кикер «зачем» ставит сам, потому что модель путает номер этапа с номером урока.Реализовано
SR-03Валидация смыслаВарианты без дублей, перестановки, критерии, обязательные записи, бюджет длины по длительности урока; невалидный урок уходит на повтор, до трёх попыток (M-5).Реализовано
SR-04Долгие операции — фоновые задачиПоиск источников, подготовка урока и следующий урок идут задачами с опросом статуса: iOS обрывает HTTP-запрос через 60 с.Реализовано
SR-05Промпты версионируютсяВерсия промптов пишется в урок и отдаётся в health; правка педагогики не требует релиза клиента.Реализовано
SR-06Кэш промптаМетодика и контекст предмета — стабильные префиксы под кэш; меняется только хвост с записями.Реализовано
SR-07Доступ по токенуВсе запросы, кроме health, требуют bearer-токен; ключ модели только в секретах сервера.Реализовано
SR-08Привязка данных к аккаунтуСервер проверяет Apple identityToken по ключам Apple и меняет его на токен аккаунта; у предмета есть владелец, чужие предметы не видны и не отдаются по id. Предметы, созданные до входа, остаются у общего владельца и доступны всем авторизованным — иначе они пропали бы у тестировщиков при обновлении.Реализовано
SR-09Push о готовности урокаНужен либо EAS-проект (ключи APNs держит Expo), либо ключ APNs .p8 и отправка из сервера — то и другое требует учётных данных. Пока разрыв закрыт иначе: возврат из фона и запуск перезапускают опрос готовности, поэтому доготовившийся урок появляется сразу.План
SR-10Задачи воркера трёх видовСобрать текущий урок, заготовить следующий, продвинуть заготовку в текущие. Заготовка живёт в предмете отдельно от текущего урока и не меняет его статус; повторный запрос предзагрузки — no-op.Реализовано
SR-11Разбор идемпотентенПовторная отправка разбора того же урока (перезапуск клиента, «Повторить») не дублирует записи и не запускает лишнюю генерацию: если следующий урок уже готов, ответ «ready».Реализовано
SR-12Очередь переживает перезапуск сервераОчередь в памяти; при старте предметы со статусом «в подготовке» ставятся в очередь заново, незавершённая предзагрузка сбрасывается.Реализовано
SR-15Именные токены тестировщиковОбщий токен остаётся админским: под ним выдаются, перечисляются и отзываются именные токены. Хранятся хешами (SHA-256), значение показывается один раз, отзыв действует сразу и не трогает остальные; видно, когда токен использовался последний раз.Реализовано
SR-13Плавная остановкаПо SIGINT/SIGTERM воркер дорабатывает текущий урок при живом сервере (до 150 с, Fly ждёт 160 с), и только потом хост останавливается; деплой посреди генерации не стоит повторного вызова модели. Замер на Fly: 22 с дожидания с ответами 200, ~10 с на перезапуск.Реализовано
SR-14Источники ищутся один разWeb search только при создании предмета; результат хранится в предмете. Предмет старого клиента без источников ищет их один раз перед первым уроком, следующие уроки такого предмета собираются без источников с предупреждением в логе (M-2).Реализовано
Замеры на реальной модели, 9 сентября: фокусы 5 с (claude-sonnet-5), план 6 с, источники с web search около 30 с, диагностика 20 с, следующий урок 18–27 с (10-минутный урок из пяти шагов — 27 с), заготовка следующего урока 30 с, оценка свободного ответа 1.4 с. Стоимость предмета с одним уроком порядка 10–20 центов; предзагрузка добавляет одну лишнюю генерацию примерно на каждый провальный или переходный урок.

Открытые вопросы

  • Порог годности заготовки. Заготовка отбрасывается при менее чем половине верных ответов; порог выбран без статистики, как и пороги этапов, и настраивается на сервере без релиза (FR-35).
  • Пороги этапов. 75/60 % и потолок в шесть уроков выбраны без статистики; после первых записей тестировщика подстроить на сервере без релиза.
  • Несколько предметов. Клиент хранит один пользовательский предмет; для второго нужен список предметов и привязка на сервере к аккаунту (FR-16, SR-08).
  • Push о готовности урока. Требует EAS-проекта или ключа APNs: нужно решение владельца, какой путь выбрать (SR-09).
  • Оценка свободных ответов. Включать серверную оценку по смыслу в сессии с офлайн-фолбэком по ключам (FR-24).
Каждое требование прослеживается до принципа метода (M-n), экрана прототипа или контракта сервера в docs/ai-content.md. Статусы обновляются вместе с релизами.
