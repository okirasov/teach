# Как подключается AI для генерации контента

Дата: 2026-09-08, обновлено 2026-09-09. Статус: сервер `server/Teach.Api` и `HttpContentService` в клиенте реализованы; сквозной контур проверен на заглушке и на реальном Claude (все вызовы, включая генерацию диагностики).

## Принцип

Клиент не зовёт модель. Он говорит с оркестратором на сервере (.NET, бриф §5.1), а оркестратор
говорит с моделью. Причины: ключи не попадают в приложение, промпты правятся без релиза в сторах,
уроки кэшируются между пользователями с похожими миссиями, стоимость под контролем.

В клиенте уже есть единственная дверь к генерации: интерфейс `ContentService`
(`mobile/src/content/types.ts`). Сейчас его реализует локальная заглушка с данными прототипа.
Подключение сервера — это вторая реализация того же интерфейса поверх HTTP, экраны не меняются.

## Что генерируется и когда

| Момент | Метод ContentService | Что делает модель | Когда показываем |
|---|---|---|---|
| Мастер, шаг «Сужение» | `suggestFocus(topic)` | 3 фокуса с описаниями по теме | сразу, ждём ответ (~2 с) |
| Мастер, шаг «Источники» | `findSources(topic, focus)` | 4 источника с уровнем доверия | сразу; web search, ~2 мин на `claude-opus-5` |
| Мастер, шаг «План» | `buildPlan(draft)` | 3 этапа плана под миссию | сразу |
| После «Готово» | `prepareFirstLesson(draft)` | стартовая диагностика | в фоне: карточка «Готовится…» → «Урок готов» |
| Открыт урок N | `prefetchNextLesson(remoteId)` | заготовка урока N+1 по записям на этот момент | незаметно; клиент ответа не ждёт |
| После каждого разбора | `prepareNextLesson(remoteId, number, records)` | следующий урок по плану и записям об усвоенном | сразу, если заготовка подошла; иначе в фоне: «Готовится…» → «Урок N · …» |
| Свободный ответ в сессии | `gradeFreeAnswer(step, text)` (добавится) | оценка по критериям вместо поиска ключевых слов | онлайн; офлайн — текущая проверка по ключам |

Повторы, справочники и глоссарий модель не трогает: сроками владеет FSRS, справочники
конденсируются из уже сгенерированных уроков на сервере.

## Контракт урока

Модель не изобретает разметку. Она заполняет фиксированную схему `Lesson`
(`mobile/src/domain/types.ts`): шаги `explain | choice | input | order | free` с полями
`recTitle`/`recNote` (будущая LearningRecord) и ссылкой на источник. Ответ модели запрашивается
как структурированный вывод (`output_config.format` с JSON-схемой), поэтому парсинг
детерминированный, а невалидный JSON невозможен на уровне API.

**Схема на проводе компактнее доменной.** У структурированного вывода жёсткий лимит сложности схемы:
полная схема шага с 21 полем и вложенными массивами (`tokens: string[][]`, `criteria: {t, keys[]}[]`)
отвергается API с ошибкой `Schema is too complex`. Поэтому модель заполняет плоский шаг из 13 полей,
а сервер разворачивает его в доменный (`ClaudeLessonModel.RawStep`):

| Поле схемы | explain | choice | input | order | free |
|---|---|---|---|---|---|
| `title` | заголовок | — | — | — | — |
| `text[]` | абзацы | варианты | группы токенов, синонимы через `\|`: `«if i were \| if i was»` | элементы | критерии `«текст \| ключ1, ключ2»` |
| `example`, `source` | пример, источник | — | — | — | — |
| `prompt`, `explain`, `recTitle`, `recNote` | — | ✓ | ✓ | ✓ | ✓ |
| `correct` (int) | — | индекс верного, `-1` — калибровка | — | — | — |
| `order` (int[]) | — | — | — | индексы в правильном порядке | — |
| `answer` | — | — | эталон | — | — |

Все поля шага обязательны: неприменимые модель заполняет пустой строкой, пустым массивом, `correct: -1`,
`order: []`. Без этого модель опускает необязательные поля, и валидатор отклоняет урок (проверено:
три подряд отказа с пустыми `explain`/`recTitle`/`recNote`). `why` («миссия · …») и `placeholder`
модель не пишет, их ставит сервер. Пустой `text` у `input` означает «принимается любой текст»
(свободный рассказ в диагностике).

Два подводных камня структурированного вывода, пойманные на живых прогонах:
- thinking считается в `max_tokens`, поэтому лимит вывода 32000, а обрезание (`stop_reason: max_tokens`)
  распознаётся явно и уходит на повтор;
- ограниченная грамматика может зациклиться внутри необязательной строки (два раза подряд на
  `placeholder`, 16k и 32k токенов до обрыва). Лишние строковые поля из схемы убраны, а на случай
  повторного сбоя есть запасной путь: тот же промпт без схемы, JSON вырезается из текста и проходит
  тот же валидатор.

Поверх схемы сервер валидирует смысл (`LessonValidator`, бриф §5.4): 2–5 вариантов без дублей и
`correct` в диапазоне, `order` — перестановка индексов, у `free` 2–5 критериев с ключами, у каждой
практики заполнены `recTitle`/`recNote`, у объяснения есть источник, длина в бюджете длительности
урока (3/5/10 мин → 1400/2200/4000 символов), один урок — одна цель. Не прошло — повтор генерации,
до `MaxAttempts`, потом статус `failed`; пользователю невалидный урок не показывается.

## Вызов модели на сервере

Модель по умолчанию — `claude-opus-5` (Anthropic SDK для .NET, пакет `Anthropic`). Форма запроса:

```
system  = [ методика teach (принципы §2 брифа), формат урока, правила валидации ]   ← cache_control
user    = [ миссия предмета, план, выбранные источники ]                            ← cache_control
        + [ последние записи об усвоенном, настройки предмета: длительность, сложность ]
        + [ «собери урок N по этапу плана 02» ]
thinking = { type: "adaptive" }, output_config = { effort: "high", format: { json_schema: Lesson } }
```

Вспомогательные вызовы мастера (фокусы, источники, план) и диагностика идут с `effort: medium`, web search
ограничен тремя запросами. Замеры живых прогонов (2026-09-09): фокусы 5 с, план 6 с, источники 2 мин 12 с,
оценка свободного ответа на `claude-haiku-4-5` 1.4 с и по смыслу («укрепления и проливы» засчитаны
как «стены и море» без совпадения ключевых слов), стартовая диагностика 20 с и 1034 токена вывода,
валидна с первой попытки: объяснение с источником, калибровка без правильного ответа, свободный рассказ
и настоящая проверка по модели Тулмина с записями «данные путают с тезисом». Урок 2 по итальянскому
после разбора с ошибкой «перепутал buongiorno и buonasera»: 18 с, 1191 токен, валиден с первой попытки,
объяснение начинается с этой ошибки, источник с разделом, три типа практики (выбор, ввод с группами
синонимов, порядок реплик).
Десятиминутный урок (бюджет 4000 символов): 27 с, 5 шагов. Прогон предзагрузки на том же предмете
(вечер 2026-09-09, три разбора подряд): заготовка следующего урока 22–30 с (699 токенов входа,
1530 из кэша, ~1600–1850 вывода); после разбора с 4 из 5 верных и без смены этапа заготовка стала
уроком за 7 с, из них почти всё — глоссарий на Haiku; после разбора, закрывшего этап (80 % и 75 %
на двух последних уроках), заготовка отброшена и урок собран заново под новый этап за ~35 с.
Уровень у новых уроков ставит сервер: «этап 02 · Первые фразы для поездки».

- **Кэш промпта.** Методика и формат урока неизменны для всех, миссия и источники — для предмета.
  Оба слоя помечены `cache_control`, меняется только хвост с записями. Это основная экономия:
  кэшированные токены стоят ~10 % от полной цены.
- **Источники.** На шаге `findSources` серверу нужен реальный поиск, а не память модели:
  серверный инструмент `web_search` с `allowed_domains` для академических и официальных
  источников, `max_uses: 5`. Уровень доверия проставляет модель по правилам из системного промпта.
- **Источники ищутся один раз.** Мастер передаёт найденные источники в `POST /subjects` (`sources`),
  и воркер их больше не ищет ни для одного урока: web search — самый долгий (30–120 с) и дорогой вызов,
  а источники предмета от урока к уроку не меняются. Если предмет создан старым клиентом без
  источников, поиск выполняется один раз перед первым уроком и сохраняется; для следующих уроков
  такого предмета сервер генерирует без источников (промпт просит опираться на общепризнанные
  материалы) и пишет предупреждение в лог. Этапы «ищу источники → отбираю по доверию» карточка
  показывает только на первом уроке; следующий урок сразу «Собираю урок N».
- **Следующий урок и этапы плана.** План из мастера хранится в предмете (`PlanJson`), текущим этапом
  владеет сервер (`PlanStage`) и двигает его только по результатам (`StagePolicy`): этап закрыт, когда
  два последних урока этапа сделаны на ≥ 75 % и ≥ 60 % с первой попытки (диагностика не в счёт);
  страховка от застревания — после шести уроков на этапе он закрывается в любом случае. Записи
  хранят номер урока и этап, по ним считаются исходы уроков. Промпт получает этап явно
  (`{STAGE}` — номер, название, описание) и записи, чуть выше границы которых строится урок.
  Уроки хранятся в истории (`Lessons`), статус несёт номер урока, `planStage` и `planTotal`;
  карточка на клиенте берёт этап с сервера. Заголовок «Урок N · …» и строку уровня
  («этап 02 · фокус») ставит сервер: модель путала номер этапа с номером урока.
- **Предзагрузка одного урока вперёд.** Когда клиент открывает урок N, он зовёт
  `POST /subjects/{id}/prefetch`; воркер собирает урок N+1 на текущем этапе по записям на этот момент
  и кладёт его в `PrefetchJson` (статус предмета не меняется, повторный вызов — no-op). При разборе
  сервер сначала решает этап (`StagePolicy`), затем смотрит на заготовку: она годится, если собрана
  на том же этапе и в разборе ≥ 50 % верных — тогда она становится текущим уроком без генерации.
  Если заготовка ещё собирается, задача «продвинуть» встаёт в очередь за ней и проверяет этап сама,
  а не выбрасывает почти готовый урок
  (`prefetched: true` в статусе, история и глоссарий как обычно). Иначе заготовка выбрасывается и урок
  генерируется заново с учётом свежих записей. Цена — одна лишняя генерация на ~каждый провальный
  или переходный урок, выигрыш — следующий урок появляется сразу после «Готово».
- **Перезапуски.** Деплой не обрывает генерацию. Стандартный ConsoleLifetime по SIGINT сразу
  останавливает хост, а Kestrel гасится первым — клиент получал бы «connection refused» на всё время
  дожидания (замерено на Fly: 35 с). Поэтому lifetime свой (`DrainingLifetime`): сигнал переводит
  воркер в дожидание, начатый урок дорабатывается при живом сервере (до `Teach:ShutdownSeconds`,
  по умолчанию 150 с; Fly ждёт `kill_timeout` 160 с), и только потом хост останавливается —
  проверено локально и на Fly (перезапуск машины посреди заготовки: 22 с дожидания с ответами 200,
  урок сохранён, ~10 с на сам перезапуск). Незавершённая предзагрузка после старта сбрасывается,
  предметы «в подготовке» ставятся в очередь заново. Клиент при опросе терпит
  сбои сети и ответы 5xx до трёх минут (`outageMs`), а 4xx считает ошибкой сразу. Очередь воркера
  живёт в памяти: при старте сервер заново ставит в очередь предметы со статусом «в подготовке». Повторный разбор того же урока (клиент перезапустился или нажал
  «Повторить») не дублирует записи и не запускает лишнюю генерацию: если следующий урок уже готов,
  ответ `ready`. Клиент при запуске вкладок продолжает ждать урок (`resumeLesson`), а не шлёт разбор снова.
- **Справочники.** После каждого урока сервер извлекает 3–6 терминов (`claude-haiku-4-5`, структурированный
  вывод) и сливает их в глоссарий предмета без дублей по термину; он приходит с уроком в `references`
  и ложится в SQLite клиента, вкладка «Справочники» показывает предмет сразу. Другие группы справочников
  (грамматика, цель) — следующий шаг конденсации.
- **Короткое имя предмета** (`POST /subjects/title`) модель даёт из формулировки темы; оно идёт в карточки,
  пиллы и в поле `name` уроков, полная формулировка хранится как описание.
- **Язык предмета** определяется на клиенте при создании по таблице языков (`domain/languages.ts`):
  код для STT и имена ru/en для пилла «Язык распознавания». Модель к этому не привлекается.
- **Проверка свободного ответа.** Дешёвая задача классификации: критерии + текст → какие покрыты.
  Здесь уместен `claude-haiku-4-5` с `max_tokens` ~256, ответ структурированный.
- **Фон.** Сервер ставит задачу в очередь после разбора; статус урока клиент читает при открытии
  «Сегодня» (`GET /subjects/{id}/next-lesson`) и по push. Готовый урок скачивается в SQLite и
  дальше доступен офлайн.
- **Промпты версионируются** отдельно от кода (таблица `prompts` с версией), в логе урока
  хранится версия промпта и id ответа модели.

## HTTP-контракт для клиента

```
POST /subjects/focus            { topic }                          → FocusOption[]
POST /subjects/title            { topic }                          → { title }   короткое имя ≤ 24 символов
POST /subjects/sources          { topic, focus }                   → 202 { jobId, status: "running" }
GET  /subjects/sources/{jobId}  → { status: "running" } | { status: "ready", items } | { status: "failed", error }
POST /subjects/plan             { topic, focus, mission }          → PlanStage[]
POST /subjects                  SubjectDraft (+ sources)           → 202 { subjectId, status: "preparing" }
GET  /subjects/{id}/lesson      → { status: "preparing"|"failed", stage: 0..2, number }
                                | { status: "ready", number, lesson, references[], planStage, planTotal, prefetched, prefetchReady }
POST /sessions/{id}/recap       { records }                        → 202 { status: "preparing" | "stored" }
POST /subjects/{id}/prefetch    → 202 { status: "queued" | "exists" | "running" | "skipped" }
POST /grade/free                { criteria, text, lang }           → { hits: boolean[] }
```

Всё, что у модели занимает больше нескольких секунд, сервер делает фоновой задачей, а клиент
опрашивает статус: iOS обрывает HTTP-запрос через 60 с, а web search у модели идёт 30–120 с.

`HttpContentService` реализует `ContentService`: `findSources` = `POST` + опрос задачи;
`prepareFirstLesson` = `POST /subjects` + опрос `GET …/lesson` до `ready` с `onStage` на каждом переходе,
возвращает урок и `remoteId`; `prepareNextLesson` = `POST /sessions/{remoteId}/recap` + опрос до
`number ≥ N`. `records` — записи разбора (`title, note, ok, stepIndex`). Для сидовых предметов
(английский, QA, история) recap только сохраняет записи (`stored`), уроки у них статичны.
Без сети мастер не запускается (поиск источников невозможен), остальное приложение работает из SQLite;
сбой генерации не блокирует: карточка предмета предлагает «Повторить».

## Стоимость (оценка)

Урок на 5 минут — примерно 2–3 тыс. токенов вывода и 6–8 тыс. на входе, из них 5–6 тыс.
кэшированных. При `claude-opus-5` ($5 вход, $25 вывод за 1M) это около $0.08–0.10 за урок,
проверка свободного ответа на Haiku — доли цента. Предзагрузка добавляет одну лишнюю генерацию
на каждый провальный или переходный разбор (по замерам — примерно каждый третий урок), то есть
+30–40 % к стоимости уроков за то, что следующий урок приходит через 5–10 с вместо 25–35.
Кэш уроков между похожими миссиями (ключ: цель урока + уровень) снижает это дальше.

## Порядок работ

1. ✅ `HttpContentService` в клиенте, флаг `EXPO_PUBLIC_CONTENT_URL`: без него — локальная заглушка. Сбой сервера не блокирует: карточка предмета предлагает «Повторить».
2. ✅ Сервер: `POST /subjects/*`, схема урока, валидация, фоновая диагностика (`server/README.md`). Прогнано с реальным Claude 2026-09-09.
3. ✅ Следующий урок после разбора: `POST /sessions/{id}/recap` сохраняет записи и ставит генерацию урока N по плану и записям; клиент опрашивает `GET /subjects/{id}/lesson` до `number ≥ N`, карточка показывает этапы. Push пока нет.
4. Оценка свободных ответов моделью в клиенте (`/grade/free` готов на сервере) с офлайн-фолбэком по ключам.
5. ✅ Глоссарий из уроков; остальные группы справочников и пометки «ОШИБКА» по записям — впереди.
