Как устроен мобильный репетитор Teach

Клиент на React Native, сервер-оркестратор на .NET с Claude API, контракт между ними и порядок работы: от мастера предмета до предзагрузки следующего урока. Страница отдаётся самим сервером и обновляется вместе с ним.

Обзор и архитектура

Teach учит любой теме по одному методу: объяснение → практика без подсказок → разбор → повторы. Ошибки становятся записями, из записей собирается следующий урок и карточки повторов. Система состоит из двух частей.

КЛИЕНТПриложениеэкраны, сессия урока, повторы (FSRS), справочники, голос и озвучка; локальная SQLite на аккаунт; работает офлайн для повторов и справочников
СЕРВЕРОркестратормастер предмета, генерация уроков структурированным выводом, валидация, этапы плана, предзагрузка, глоссарий, оценка свободных ответов
МОДЕЛЬClaude APIopus — уроки и поиск источников (web search); sonnet — фокусы, имя, план; haiku — оценка и глоссарий

Клиент никогда не держит ключей модели и не планирует обучение: он ходит только в ContentService, реализация которого включается адресом сервера. Всё, что у модели занимает дольше нескольких секунд, сервер делает фоновой задачей, а клиент опрашивает статус, потому что iOS обрывает HTTP-запрос через 60 секунд.

Поток одного предмета

01Мастертема → фокус → миссия → источники (web search) → план на этапы
02Диагностикаурок 1: калибровка без правильного ответа, свободный рассказ, одна проверка без подготовки («СТАРТ»)
03Урок Nобъяснение с источником и 2–3 практики, собранные по записям предыдущих разборов и этапу плана
04Разборзаписи уходят на сервер; решается этап; заготовка N+1 отдаётся сразу или собирается заново
2

Клиент

React Native + Expo SDK 57, Expo Router, TypeScript, zustand, jest-expo. Токены цвета и типографики повторяют DESIGN.md прототипа: Golos Text и IBM Plex Mono, светлая и тёмная темы.

Структура

ПапкаЧто там
app/экраны Expo Router: вход, интро, вкладки (Сегодня, Повторы, Справочники, Предметы), сессия урока, разбор, мастер предмета, настройки предмета, профиль
src/domain/типы урока и шагов, FSRS (ts-fsrs), языки, демо-предметы (demo/en, demo/speak)
src/content/ContentService: HTTP-реализация с опросом задач и локальная заглушка для разработки без сервера
src/features/движок сессии (чистые функции без React), план и этапы, повторы, справочники, подготовка предмета, озвучка
src/store/zustand-сторы: auth, progress, session, reviews, refs, settings; персистентные срезы пишутся в kv локальной БД
src/db/expo-sqlite на аккаунт (teach-<accountId>.db), версионированные миграции, репозитории карточек, справочников и kv, засев демо
src/voice/распознавание речи (expo-speech-recognition, симуляция для web) и озвучка (expo-speech), деление текста по письменности

Что важно знать

  • Сессия урока — чистый движок: активный шаг и показанный, ответы пройденных шагов заморожены, свайпы назад и вперёд до активного. Крестик сохраняет снимок сессии в предмете, следующее открытие того же урока продолжает с места остановки.
  • Проверка ответов на устройстве: выбор и порядок точно, ввод по группам синонимов, свободный ответ по ключевым словам критериев. Серверная оценка по смыслу есть в API, в сессии пока не включена.
  • Повторы: одна учебная точка — одна карточка; сроками владеет FSRS без краткосрочных шагов (ошибка → 1 день, успех → 3 дня). Карточка знает свой предмет, поэтому язык распознавания и озвучки в повторах берётся у него.
  • Голос никогда не блокирует: без разрешения или без голоса для языка кнопки просто не рисуются, текстовый ввод доступен всегда.
  • Один пользовательский предмет плюс два демо. Демо статичны и сгенерированы этим же сервером; следующих уроков у них нет.
3

Сервер

Минимальный API на .NET 10 с EF Core и SQLite на томе Fly. Один процесс: HTTP-обработчики, фоновая очередь уроков (LessonWorker), задачи поиска источников, плавная остановка.

Генерация урока

  • Структурированный вывод по схеме. Модель заполняет плоскую схему шага; сервер разворачивает её в доменный урок. Заголовок карточки «Урок N · …», строку уровня «этап 0N · фокус» и кикер «зачем» ставит сервер сам, потому что модель путает номер этапа с номером урока.
  • Валидация смысла (LessonValidator): варианты без дублей, перестановки, критерии, обязательные записи, бюджет длины по длительности урока (3/5/10 минут → 1400/2200/4000 символов), не больше семи шагов. Невалидный урок уходит на повтор, до трёх попыток.
  • Кэш промпта. Методика и контекст предмета — стабильные префиксы с cache_control, меняется только хвост с записями.
  • Источники ищутся один раз, при создании предмета, и хранятся в нём. Для следующих уроков web search не запускается.
  • Этап плана решается сервером по результатам (StagePolicy): этап закрыт, когда два последних урока сделаны на ≥ 75 % и ≥ 60 % с первой попытки, диагностика не в счёт; страховка — шесть уроков на этапе.
  • Предзагрузка. Когда клиент открывает урок N, сервер заготавливает N+1 по записям на этот момент. После разбора заготовка отдаётся сразу, если этап не сменился и верных ответов не меньше половины; иначе выбрасывается и урок собирается заново. Разбор, пришедший во время заготовки, дожидается её.
  • Глоссарий. После каждого урока haiku извлекает 3–6 терминов, они сливаются в справочник предмета без дублей и приходят вместе с уроком.
  • Перезапуски. Повторный разбор того же урока идемпотентен; очередь в памяти, при старте предметы «в подготовке» ставятся заново; по SIGINT воркер дорабатывает текущий урок при живом сервере (DrainingLifetime), Fly ждёт до 160 секунд.

API для интеграций и тестов

База: https://teach-tutor-api.fly.dev. Все маршруты, кроме /health и документации, требуют общий токен сервера в заголовке Authorization: Bearer <token>. Токен выдаёт владелец проекта; в документации его нет. Интерактивная справка с формами запросов: /scalar, машинное описание: /openapi/v1.json.

Каждый вызов генерации тратит деньги: предмет с диагностикой и одним уроком стоит порядка 10–20 центов, поиск источников — самая дорогая часть. Для проверки формата ответов достаточно одного предмета; повторные разборы того же урока бесплатны, сервер их не генерирует заново.

Маршруты

Метод и путьНазначение
GET /healthСостояние сервера: { ok, model, prompts }. Без токена.
POST /subjects/focus{ topic } → три фокуса [{ t, d }].
POST /subjects/title{ topic } → { title }, короткое имя до 24 символов.
POST /subjects/sources{ topic, focus } → 202 { jobId, status: "running" }. Поиск идёт в фоне.
GET /subjects/sources/{jobId}{ status: "running" } | { status: "ready", items: [{ id, t, m, trust }] } | { status: "failed", error }.
POST /subjects/plan{ topic, focus, mission } → этапы [{ n, t, d }].
POST /subjectsчерновик предмета → 202 { subjectId, status: "preparing" }; диагностика готовится в фоне.
GET /subjects/{id}/lessonстатус подготовки и текущий урок, см. форматы.
GET /subjects/{id}/lessonsвсе уроки предмета по номерам [{ number, lesson }]; по ним приложение восстанавливает вопросы старых карточек повторов.
POST /sessions/{id}/recapзаписи разбора → 202 { status: "preparing" | "ready" | "stored" }; для демо-id только stored.
POST /subjects/{id}/prefetchзаготовить следующий урок → 202 { status: "queued" | "exists" | "running" | "skipped" }.
POST /grade/free{ criteria: [{ t, keys }], text, lang } → { hits: boolean[] }.

Сценарий от начала до второго урока

Так ходит приложение; тем же путём можно прогнать сервер из терминала. Токен положите в переменную TOKEN.

U=https://teach-tutor-api.fly.dev
H="Authorization: Bearer $TOKEN"

# 1. Здоровье и фокусы
curl -s $U/health
curl -s -X POST -H "$H" -H 'Content-Type: application/json' $U/subjects/focus \
  -d '{"topic":"Итальянский для поездки"}'

# 2. Источники: задача + опрос (30–120 с)
JOB=$(curl -s -X POST -H "$H" -H 'Content-Type: application/json' $U/subjects/sources \
  -d '{"topic":"Итальянский для поездки","focus":"Первые фразы для поездки"}' | jq -r .jobId)
until curl -s -H "$H" $U/subjects/sources/$JOB | tee /tmp/src.json | grep -q '"ready"'; do sleep 5; done

# 3. План и предмет (источники из мастера передаём в sources — сервер больше их не ищет)
PLAN=$(curl -s -X POST -H "$H" -H 'Content-Type: application/json' $U/subjects/plan \
  -d '{"topic":"Итальянский для поездки","focus":"Первые фразы для поездки","mission":"объясниться в кафе и на вокзале"}')
SID=$(jq -n --argjson s "$(jq .items /tmp/src.json)" --argjson p "$PLAN" \
  '{topic:"Итальянский для поездки",title:"Итальянский",focus:"Первые фразы для поездки",
    mission:"объясниться в кафе и на вокзале",sourceIds:[$s[].id],sources:$s,plan:$p,durationMinutes:5}' \
  | curl -s -X POST -H "$H" -H 'Content-Type: application/json' $U/subjects -d @- | jq -r .subjectId)

# 4. Диагностика: опрос до ready (≈ 20 с)
until curl -s -H "$H" $U/subjects/$SID/lesson | tee /tmp/l1.json | grep -q '"status":"ready"'; do sleep 3; done
jq '.lesson.steps[] | {type, recTitle}' /tmp/l1.json

# 5. Предзагрузка второго урока, пока «идёт» первый
curl -s -X POST -H "$H" $U/subjects/$SID/prefetch

# 6. Разбор: записи с номером урока → урок 2 (сразу из заготовки или ≈ 25 с)
curl -s -X POST -H "$H" -H 'Content-Type: application/json' $U/sessions/$SID/recap \
  -d '{"records":[{"title":"Самооценка ≠ уровень","note":"","ok":true,"stepIndex":1,"lessonNumber":1},
                  {"title":"Вежливое Lei идёт с 3-м лицом","note":"","ok":false,"stepIndex":3,"lessonNumber":1}],
       "durationMinutes":5}'
until curl -s -H "$H" $U/subjects/$SID/lesson | tee /tmp/l2.json | grep -q '"number":2,"lesson"'; do sleep 3; done
jq '{title:.lesson.lessonTitle, level:.lesson.level, prefetched, planStage, planTotal}' /tmp/l2.json

# 7. Оценка свободного ответа по смыслу
curl -s -X POST -H "$H" -H 'Content-Type: application/json' $U/grade/free \
  -d '{"criteria":[{"t":"Есть приветствие","keys":["buongiorno"]}],"text":"Buonasera, un caffè per favore","lang":"ru"}'
Поле stage в статусе ready отсутствует (null не сериализуется), поэтому в скриптах проверяйте "number":N, а не "stage":null. Идентификаторы демо-предметов клиента (en, speak) сервер не знает: разбор по ним только сохраняет записи.

Форматы данных

Статус урока

{ "status": "preparing", "stage": 0 | 1 | 2, "number": 2 }        // ищу источники → отбираю → собираю
{ "status": "failed",    "stage": 2, "number": 2 }
{ "status": "ready", "number": 2, "planStage": 0, "planTotal": 5,
  "prefetched": true,      // урок пришёл из заготовки
  "prefetchReady": false,  // заготовка следующего уже лежит на сервере
  "lesson": { … }, "references": [ { "id", "group", "title", "updatedAfter", "rows": [ { "sec"?, "k", "v", "weak" } ] } ] }

Урок и шаги

{ "name": "Итальянский", "level": "этап 01 · Первые фразы для поездки",
  "lessonTitle": "Урок 2 · Карта первых слов", "diagnostic": false,
  "steps": [
    { "type": "explain", "why": "миссия · …", "title": "…", "paras": ["…","…"], "example": "…", "source": "Название, раздел" },
    { "type": "choice",  "prompt": "…", "options": ["…"], "correct": 1,          "explain": "…", "recTitle": "…", "recNote": "…" },
    { "type": "input",   "prompt": "…", "placeholder": "…", "tokens": [["un","uno"],["per favore"]], "answer": "…", "voice": "…", "explain": "…", "recTitle": "…", "recNote": "…" },
    { "type": "order",   "prompt": "…", "items": ["…"], "correct": [1,0,2],     "explain": "…", "recTitle": "…", "recNote": "…" },
    { "type": "free",    "prompt": "…", "criteria": [{ "t": "…", "keys": ["…"] }], "explain": "…", "recTitle": "…", "recNote": "…" }
  ] }
  • correct: -1 у выбора — калибровка без правильного ответа (бейдж «ПРИНЯТО»); пустой tokens у ввода принимает любой текст.
  • source может заканчиваться на «· доверие среднее/низкое» — клиент показывает это предупреждением; «высокое» сервер вырезает.
  • recTitle и recNote — запись об усвоенном: она становится карточкой повтора и уходит в разбор.

Черновик предмета

{ "topic": "…", "title": "…", "focus": "…", "mission": "…",
  "sourceIds": ["src-0", "src-2"], "sources": [ { "id", "t", "m", "trust": "high"|"mid"|"low" } ],
  "plan": [ { "n": "01", "t": "…", "d": "…" } ],   // любое число этапов
  "durationMinutes": 3 | 5 | 10 }

Локальный запуск

Сервер

cd server/Teach.Api
export ANTHROPIC_API_KEY=…            # без ключа — заглушка модели (Teach__Model=stub)
dotnet run                            # http://0.0.0.0:5080, база teach.db рядом
curl localhost:5080/health

Настройки через переменные Teach__*: ApiToken (пустой — открытый режим только локально), Db, Model (auto/stub/claude), StageDelayMs, DurationMinutes, ShutdownSeconds.

Клиент

cd mobile && npm install
EXPO_PUBLIC_AUTH_LOCAL=1 EXPO_PUBLIC_VOICE_SIM=1 npx expo start --web      # быстрый просмотр в браузере
EXPO_PUBLIC_CONTENT_URL=http://<ip>:5080 EXPO_PUBLIC_CONTENT_TOKEN=… npx expo start   # с локальным сервером

Флаги: EXPO_PUBLIC_AUTH_LOCAL — вход локальной сессией без провайдера; EXPO_PUBLIC_VOICE_SIM — симуляция распознавания; EXPO_PUBLIC_CONTENT_URL и EXPO_PUBLIC_CONTENT_TOKEN — сервер, без них мастер работает на локальной заглушке.

Деплой и релиз

Сервер на Fly.io

cd server/Teach.Api                   # здесь Dockerfile и fly.toml
fly deploy --remote-only
fly logs --app teach-tutor-api

Секреты: ANTHROPIC_API_KEY и Teach__ApiToken через fly secrets set. База на томе teach_data в /data. Деплой безопасен посреди генерации: воркер дорабатывает урок при живом сервере, потом машина перезапускается (≈ 10 с паузы), незавершённые предметы ставятся в очередь заново. Отдельного домена не нужно: адрес teach-tutor-api.fly.dev с HTTPS даёт Fly.

iOS в TestFlight

cd mobile/ios
export EXPO_PUBLIC_CONTENT_URL=https://teach-tutor-api.fly.dev EXPO_PUBLIC_CONTENT_TOKEN=…
xcodebuild -workspace Teach.xcworkspace -scheme Teach -configuration Release -sdk iphoneos \
  -destination 'generic/platform=iOS' -archivePath build-device/Teach.xcarchive \
  -allowProvisioningUpdates DEVELOPMENT_TEAM=… archive
xcodebuild -exportArchive -archivePath build-device/Teach.xcarchive \
  -exportOptionsPlist ../ExportOptions.plist -exportPath build-device/export -allowProvisioningUpdates

Перед сборкой поднять ios.buildNumber в app.json и CFBundleVersion в Info.plist. Адрес сервера и токен зашиваются в бандл на этапе сборки.

Тесты и наблюдение

cd server && dotnet test                 # валидатор, политика этапов, API-сценарии, миграция схемы
cd mobile && npx tsc --noEmit && npx jest # движок сессии, FSRS, сторы, HTTP-контракт, озвучка

Серверные API-тесты идут на заглушке модели и проходят весь путь: создание предмета, диагностика, разбор, этапы по результатам, предзагрузка, повторный разбор. В логах Fly видны вызовы модели с токенами и временем, готовность уроков, заготовки и продвижения, дожидание при остановке.
